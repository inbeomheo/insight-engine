# Luna 품질 우선 생성 적용 기록

## 최종 정책

- 공개 모델 목록과 기본 생성/보조 모델: `cliproxyapi/gpt-5.6-luna`.
- 추론 노력: 기본·근거 선택·작성·보정 `medium`, 독립 근거 검토 `high`.
- 원문 문장 번호 선택 → 코드가 원문 인용 확정 → 작성 → 언어/길이/메타 검사 및 별도 모델 근거 검토 → 최대 2회 보정.
- 보정 후에도 실패하면 초안을 성공 결과로 반환하지 않는다. 사용량 한도 오류는 재시도하거나 다른 모델로 전환하지 않는다.
- 2만 자당 근거 선택 1회, 작성 1회, 검토 1회, 보정 필요 시 수정+재검토 최대 2쌍. 단계 전체 제한 240초, 요청당 60초 이내.
- 추가 호출마다 기존 사용량 임대 검사를 거치며 성공 결과의 토큰은 전체 단계 합계다.
- 실시간 경로도 검토 완료 후 본문을 전송한다. 첫 본문 표시가 늦어지는 품질 우선 동작이다.
- 구조화 변환과 스타일 미지정 호출은 기존 형식을 유지한다. 한국어 짧은 자막 원문 반환도 유지하되 다른 출력 언어 요청은 이 우회를 사용하지 않는다.
- SEO/GEO 파서용 고정 라벨은 예외로 유지한다. 다른 언어의 일반 제목·표 값·본문에 한국어가 섞이는 것은 보정 대상이다.
- 기존 노트·인증·환경변수 실파일은 수정하지 않았다. 기존 캐시를 삭제하지 않고 새 키 버전으로 분리했다.

## 검증

- 최종 Luna 설정 및 풀 분리 수정으로 백엔드: 4,738 passed, 5 skipped, 32 subtests passed.
- 프론트엔드: 358 passed / 52 files, TypeScript 검사 및 Next.js 빌드 성공.
- 새 품질 경로 검사: 정상 생성·사용량 합산·추론 단계·잘못된 문장 번호·JSON 오류·불완전 응답·언어 혼합·분량 초과·보정 한도·시간 초과·임대 상실·사용량 오류 무재시도·원문 분할·검토 전 스트림 노출 차단 등을 포함.
- 최초 Luna 실호출은 429 `model_cooldown`으로 차단됐다. 당시 16,061초 대기는 Luna 자체 소진이 아니라 Spark의 `usage_limit_reached`가 계정 전체로 잘못 전파된 결과였다. 실제 계정 조회에서 일반 풀 1% 사용 가능, Spark 5시간 풀 100%를 확인했다.
- CLIProxyAPI v7.2.152에 `patches/cliproxyapi-quota-pools.patch`를 적용해 Spark 별도 풀과 Luna·GPT-5.5 공유 풀로 차단을 분리했다. 로컬 수정판 재시작 후 Spark 429 → Luna 200 → GPT-5.5 200 → Spark 즉시 429 `model_cooldown`을 실호출로 확인했다. 실제 사용량 제한은 유지하며 계정·키·저장 파일은 삭제하지 않았다.
- Go 인증/선택 패키지 전체 테스트, 수정판 실행 파일 빌드, 앱 관련 테스트 83건 통과. Dockerfile에도 고정 커밋 패치와 분리 회귀 테스트를 추가했으나 이번 수정판 Docker 이미지 빌드는 로컬에서 실행하지 않았다.
- Luna 앱 생성 서비스의 한국어 요약 실검사 통과: 근거 선택·작성·독립 검토 3회, 14.28초, 본문 177자, 합계 2,871토큰. 추론 요청은 선택·작성 medium, 검토 high이며 서버 내부 추론 계산량 자체를 증명하는 검사는 아니다. 테스트용 Flask 실행 문맥을 제공했으며 계정 데이터 저장이나 브라우저 경로는 호출하지 않았다.
- 전환 전 동일 흐름의 Spark 실검사에서는 요약/SEO/GEO/튜토리얼/Q&A/영어 요약/일본어 요약 7건이 검사 통과. 이 결과를 Luna 실검증으로 간주하지 않는다.
- 이번 변경에서는 영상 다운로드·실제 계정 저장·브라우저 전체 흐름·운영 배포는 재검증하지 않았다.

## 한계

같은 모델의 별도 검토는 사실성을 보장하지 않는다. 자동 언어 검사 역시 문자권 기반 검사라 모든 언어 혼합을 탐지하지는 못한다. 원문 밖 사실과 의미 왜곡의 잔여 위험은 존재한다. Luna의 한/영/일 전체 형식 및 브라우저 실시간 경로 재검사는 별도 검증 범위다.
