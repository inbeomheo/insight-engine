## 이번에 확인하여 수정한 오류

1. **다중 자료 생성과 재시도**: 배치 작업자가 YouTube만 처리하던 원인을 수정했다.
   단일 생성에서 사용하는 URL 판별·웹 수집·통합 수집을 적용하고, 실패한 주소는 입력 목록에 남긴다.
   성공 결과만 저장하고 성공 주소만 제거한다. 데스크톱·375px 모바일 재시도를 실제 브라우저에서 검사한다.
2. **생성 설정 전달**: 배치에 상세도·자막 언어·웹 검색·에이전트 옵션을 전달하고,
   통합 생성에는 자막 언어를 전달한다. 에이전트 작성 단계의 고정 한국어 지시를 제거하고
   기존 언어·문체·길이 정의와 상세도 설정을 적용한다. 검색을 끄면 에이전트도 검색하지 않는다.
   교정 단계도 작성 단계 이상의 출력 한도를 확보하고, 길이 제한으로 중단된 교정본은
   온전한 초안을 덮어쓰지 않는다.
3. **사용자·비용 경계**: 새 스레드에 인증된 사용자 ID를 명시적으로 전달한다.
   배치 전체 사용량 예약은 한 번이며 비용 시작 이후 실패나 잠금 상실 때의 계약을 유지한다.
   외부 수집의 사설 주소 차단과 클라이언트 수집기 강제 금지도 검사한다.
4. **노트 격리**: 그래프·역방향 연결을 로그인 사용자 범위로 제한하고 계정 전환 시
   이전 화면 상태와 늦게 도착한 응답이 섞이지 않게 했다. 같은 노트 ID를 가진 두 사용자의
   실제 임시 Chroma 저장소 검색·수정·연결을 검증한다.
5. **Anki 카드**: 객관식 선택지를 앞면에 포함하고 정답·해설을 분리한다.
   동일 질문 복수 카드의 식별 충돌과 순서 변경을 검사하며 기존 단일 카드 식별은 유지한다.
   브라우저가 실제 Flask에서 내려받은 `.apkg`의 압축·SQLite 카드 내용·출처·태그를 검사한다.
6. **응답 시간 제한**: 응답 헤더뿐 아니라 JSON·파일 본문을 모두 받을 때까지
   시간 제한과 사용자 취소 연결을 유지한다. 본문 수신 정지 회귀 검사를 추가했다.
7. **검증 자체의 신뢰성**: 항상 참인 단정과 제거된 API 키/로그인 화면 가정을 정리했다.
   로그인·로그아웃·세션 저장·히스토리 검색·사용량 합산·키보드·메모리를 실제 동작으로 검사한다.
   브라우저 실행 산출물은 추적 중인 인증 예제가 아닌 `tests/test-results/`에 저장한다.
8. **의존성·배포**: 프론트엔드 잠금 파일의 취약 의존성을 패치했다.
   자동 검증과 외부 Docker 게시·Railway 배포를 분리하여 배포 미설정 때문에 검증이 실패하지 않게 했다.
   배포를 명시적으로 켰는데 필수 설정이 없거나 이미지 게시가 실패하면 오류로 중단한다.

React 검토 지침에 따라 계정별 화면 재생성, 요청 정리, 좁은 상태 구독과 입력 보존을 확인했다.
삭제·마이그레이션을 수반하는 저장 형식 변경은 하지 않았다.

## 확인하지 못한 외부 환경과 운영 주의

- 실제 ChatMock/YouTube 연동 생성 5개 검사는 `E2E_LIVE_GENERATION=1`과 정상 연결이 필요하다.
  현재 8000번 포트는 다른 모델 서비스이며 이를 ChatMock으로 간주하거나 변경하지 않았다.
- 브라우저 로그인은 응답을 대체해 앱의 세션 동작을 검증했다. 실제 Supabase 계정 로그인·
  클라우드 데이터 연동·Railway 운영 배포를 검증했다고 주장하지 않는다.
- 운영 DB에 migration 008/009를 실행하거나 데이터를 삭제·교체하지 않았다.
  기존 운영 환경 적용은 백업과 사용자 승인이 먼저 필요하다.
- 로컬 Docker 실행 도구가 없어 이미지 빌드·실행 근거는 최종 GitHub Actions 결과로 확인한다.
- Chroma 서버 취약점 예외는 안전한 패치가 나오는 즉시 제거해야 하며,
  현재 지원은 서버를 외부에 노출하지 않는 embedded 단일 백엔드 프로세스 구성이다.

따라서 이 기록은 검증한 코드 경로의 회귀 결과이며, 모든 외부 서비스와 운영 환경의 무결점 보장은 아니다.
